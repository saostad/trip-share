# Requirements Document

## Introduction

TripShare is a web application for splitting trip expenses among participants. Users authenticate with Google, create trips with named participants, log expenses (recording who paid and who shared the cost), and view net balances with simplified settlement transactions. The application supports multi-user collaboration: trip owners can generate share links to invite collaborators who can manage expenses but not trip settings. The application uses Firebase for authentication, real-time data sync, and hosting.

## Glossary

- **App**: The TripShare web application built with React, TypeScript, and Firebase
- **User**: An authenticated person using the App via Google Sign-In
- **Owner**: The User who created a Trip; has full control over trip settings, participants, share links, and deletion
- **Collaborator**: A User who joined a Trip via a Share_Link; can add, edit, and delete any Expense in the Trip but cannot manage trip settings
- **Trip**: A named container owned by a User that groups participants and their shared expenses, with optional collaborators
- **Participant**: A named string within a Trip representing someone who can pay for or share expenses (not necessarily a registered User)
- **Expense**: A record within a Trip capturing a description, date, amount, who paid, and who shared the cost
- **Balance**: The net amount a Participant is owed (positive) or owes (negative) after all expenses are calculated
- **Settlement_Transaction**: A simplified payment instruction indicating one Participant should pay another a specific amount to settle debts
- **Share_Link**: A revocable URL generated by the Owner that allows any authenticated User to join the Trip as a Collaborator
- **Share_Token**: A random string stored on the Trip document that forms part of the Share_Link; set to null when the link is revoked
- **Dashboard**: The main page listing all Trips where the current User is either the Owner or a Collaborator
- **Trip_Detail_Page**: The page showing expenses, the add-expense form, and balances for a specific Trip
- **Join_Trip_Page**: The page that handles the share link join flow at `/join/:shareToken`
- **Auth_Context**: The React context providing authentication state throughout the App
- **Firestore**: The Cloud Firestore database providing real-time data sync via onSnapshot listeners

## Requirements

### Requirement 1: Google Authentication

**User Story:** As a user, I want to sign in with my Google account, so that I can securely access my trips without creating a separate account.

#### Acceptance Criteria

1. WHEN a user clicks the Google Sign-In button, THE App SHALL initiate the Google OAuth flow using Firebase SDK v12+ (modular tree-shakable imports)
2. WHEN authentication succeeds, THE App SHALL store the auth state in Auth_Context and redirect the user to the Dashboard
3. WHEN an unauthenticated user attempts to access a protected route, THE App SHALL redirect the user to the login page
4. WHILE a user is authenticated, THE App SHALL display the user's Google profile picture and name in the top-right header area
5. WHEN a user clicks the Logout button, THE App SHALL sign out the user and redirect to the login page
6. IF authentication fails, THEN THE App SHALL display an error toast notification using sonner

### Requirement 2: Dashboard Display

**User Story:** As a user, I want to see all trips I own or collaborate on, so that I can quickly access and manage my travel expenses.

#### Acceptance Criteria

1. WHEN the Dashboard loads, THE App SHALL display all Trips where the current user's UID matches the ownerId OR the current user's UID is contained in the collaboratorIds array
2. THE App SHALL display each Trip as a card showing: trip name, number of participants with avatar initials, total amount spent, last activity timestamp, and a label indicating whether the user is the Owner or a Collaborator
3. WHEN no trips exist for the current user, THE App SHALL display an empty state with guidance to create a new trip
4. THE App SHALL display a green "New Trip" button on the Dashboard
5. WHEN trip data changes in Firestore, THE App SHALL update the Dashboard in real-time via onSnapshot listeners

### Requirement 3: Create Trip

**User Story:** As a user, I want to create a new trip with named participants, so that I can begin tracking shared expenses.

#### Acceptance Criteria

1. WHEN a user clicks the "New Trip" button, THE App SHALL open a shadcn Dialog containing the TripForm
2. WHEN creating a trip, THE App SHALL require a non-empty trip name
3. THE App SHALL provide a dynamic participant list where the user can add and remove participant names
4. WHEN a user submits a valid trip form, THE App SHALL create a Trip document in Firestore with the ownerId set to the current user's UID, the provided name, participants array, an empty collaboratorIds array, a null shareToken, and timestamps
5. IF the trip name is empty on submission, THEN THE App SHALL display a validation error and prevent submission
6. WHEN a trip is successfully created, THE App SHALL close the dialog and display a success toast notification

### Requirement 4: Edit Trip (Owner Only)

**User Story:** As a trip owner, I want to edit a trip's name and participants, so that I can correct mistakes or add new members.

#### Acceptance Criteria

1. WHEN the Owner initiates trip editing, THE App SHALL display the TripForm pre-filled with the existing trip name and participants
2. WHEN the Owner submits the edited trip form with valid data, THE App SHALL update the Trip document in Firestore and update the updatedAt timestamp
3. IF the edited trip name is empty on submission, THEN THE App SHALL display a validation error and prevent submission
4. THE App SHALL hide the edit trip option from Collaborators

### Requirement 5: Delete Trip (Owner Only)

**User Story:** As a trip owner, I want to delete a trip, so that I can remove trips I no longer need.

#### Acceptance Criteria

1. WHEN the Owner initiates trip deletion, THE App SHALL display a confirmation dialog before proceeding
2. WHEN the Owner confirms trip deletion, THE App SHALL delete the Trip document and all associated Expense documents from Firestore
3. WHEN a trip is successfully deleted, THE App SHALL display a success toast notification and return the user to the Dashboard
4. THE App SHALL hide the delete trip option from Collaborators

### Requirement 6: Trip Detail Page

**User Story:** As a user, I want to view a trip's details including expenses and balances, so that I can understand the financial state of the trip.

#### Acceptance Criteria

1. WHEN a user navigates to a Trip_Detail_Page, THE App SHALL display a header with the trip name, a back button, participant avatars, and a list of collaborators (Google display names and avatars)
2. THE App SHALL display two main sections: an expense list (newest first) and an "Add Expense" form, side-by-side on desktop and stacked on mobile
3. WHEN expense data changes in Firestore, THE App SHALL update the Trip_Detail_Page in real-time via onSnapshot listeners
4. WHEN a user clicks the back button, THE App SHALL navigate back to the Dashboard
5. WHEN the current user is the Owner, THE App SHALL display trip management controls: edit trip button, manage participants, share link section, and delete trip button
6. WHEN the current user is a Collaborator, THE App SHALL display only expense CRUD controls and hide all trip management options

### Requirement 7: Add Expense

**User Story:** As a user (owner or collaborator), I want to add an expense to a trip, so that I can record who paid and who shared the cost.

#### Acceptance Criteria

1. THE App SHALL display an expense form with fields for: description (text), date (date picker defaulting to today), amount (number with currency $), paid by (dropdown of participants), and shared by (multi-select checkboxes of all participants)
2. WHEN a user submits a valid expense form, THE App SHALL create an Expense document in Firestore with the provided fields and a createdAt timestamp
3. IF the amount is zero or negative on submission, THEN THE App SHALL display a validation error and prevent submission
4. IF no participants are selected in "shared by" on submission, THEN THE App SHALL display a validation error and prevent submission
5. WHEN an expense is successfully created, THE App SHALL clear the form and display a success toast notification
6. THE App SHALL display all currency values formatted as $X.XX

### Requirement 8: Edit Expense

**User Story:** As a user (owner or collaborator), I want to edit an existing expense, so that I can correct errors in recorded transactions.

#### Acceptance Criteria

1. WHEN a user initiates expense editing, THE App SHALL display the ExpenseForm pre-filled with the existing expense data
2. WHEN a user submits the edited expense form with valid data, THE App SHALL update the Expense document in Firestore
3. IF the edited amount is zero or negative on submission, THEN THE App SHALL display a validation error and prevent submission
4. IF no participants are selected in "shared by" on submission, THEN THE App SHALL display a validation error and prevent submission

### Requirement 9: Delete Expense

**User Story:** As a user (owner or collaborator), I want to delete an expense, so that I can remove incorrectly recorded transactions.

#### Acceptance Criteria

1. WHEN a user initiates expense deletion, THE App SHALL display a confirmation dialog before proceeding
2. WHEN a user confirms expense deletion, THE App SHALL delete the Expense document from Firestore
3. WHEN an expense is successfully deleted, THE App SHALL display a success toast notification

### Requirement 10: Balance Calculation

**User Story:** As a user, I want to see net balances for all participants, so that I can understand who owes money and who is owed.

#### Acceptance Criteria

1. THE App SHALL calculate each Participant's net balance by adding the full expense amount to the payer's balance and subtracting each sharer's equal portion (amount divided by number of sharers) from their balance
2. THE App SHALL display positive balances in green (emerald-500) indicating the participant is owed money
3. THE App SHALL display negative balances in red indicating the participant owes money
4. WHEN expenses change, THE App SHALL recalculate and update balances in real-time

### Requirement 11: Simplified Settlements

**User Story:** As a user, I want to see simplified payment instructions, so that I can settle debts with the minimum number of transactions.

#### Acceptance Criteria

1. THE App SHALL compute simplified settlement transactions using a greedy algorithm that pairs the largest debtor with the largest creditor iteratively
2. THE App SHALL display each Settlement_Transaction as "[Debtor] pays [Creditor] $X.XX"
3. THE App SHALL ignore balances within a $0.01 threshold when determining debtors and creditors
4. THE App SHALL round transaction amounts to the nearest cent (two decimal places)
5. FOR ALL sets of expenses and participants, THE App SHALL produce settlement transactions where the sum of settlements from each debtor equals their total debt (within rounding tolerance)

### Requirement 12: Real-Time Data Synchronization

**User Story:** As a user, I want my data to update in real-time, so that I see the latest information without refreshing the page.

#### Acceptance Criteria

1. THE App SHALL use Firestore onSnapshot listeners in custom hooks (useTrips, useExpenses, useTrip) to subscribe to data changes
2. WHEN a local write occurs, THE App SHALL reflect the change immediately through Firebase's latency compensation before server confirmation
3. WHEN a component unmounts, THE App SHALL unsubscribe from all active onSnapshot listeners to prevent memory leaks

### Requirement 13: Security and Access Control

**User Story:** As a user, I want my trip data to be secure and properly access-controlled, so that only authorized users can view and modify data.

#### Acceptance Criteria

1. THE Firestore security rules SHALL allow read operations on a Trip document only when the authenticated user's UID matches the document's ownerId field OR the user's UID is contained in the document's collaboratorIds array
2. THE Firestore security rules SHALL allow update and delete operations on a Trip document only when the authenticated user's UID matches the document's ownerId field
3. THE Firestore security rules SHALL allow creation of a Trip document only when the authenticated user's UID matches the ownerId in the submitted data
4. THE Firestore security rules SHALL allow read and write operations on Expense documents only when the authenticated user's UID matches the ownerId of the parent Trip document OR the user's UID is contained in the parent Trip's collaboratorIds array
5. THE Firestore security rules SHALL validate that expense amount is greater than zero
6. THE Firestore security rules SHALL validate that sharedBy is a non-empty array
7. THE Firestore security rules SHALL validate that paidBy is contained in the parent Trip's participants array
8. THE Firestore security rules SHALL allow a user to add their own UID to a Trip's collaboratorIds array when the user presents the correct shareToken value matching the Trip's shareToken field

### Requirement 14: Share Link Management (Owner Only)

**User Story:** As a trip owner, I want to generate and manage a share link, so that I can invite collaborators to my trip.

#### Acceptance Criteria

1. WHEN the Owner clicks "Generate Share Link", THE App SHALL create a random Share_Token, store it on the Trip document, and display the full Share_Link URL
2. THE App SHALL display the Share_Link URL with a copy-to-clipboard button
3. WHEN the Owner clicks "Revoke Link", THE App SHALL set the Trip's shareToken field to null, disabling the link
4. WHEN the Owner clicks "Regenerate Link" after revocation, THE App SHALL generate a new Share_Token and display the updated Share_Link URL
5. THE App SHALL display the share link management section only to the Owner on the Trip_Detail_Page
6. WHILE the shareToken is null, THE App SHALL display the share link section as disabled with an option to generate a new link

### Requirement 15: Join Trip via Share Link

**User Story:** As a user with a share link, I want to join a trip as a collaborator, so that I can participate in expense tracking.

#### Acceptance Criteria

1. WHEN an authenticated user navigates to `/join/:shareToken`, THE Join_Trip_Page SHALL look up the Trip with the matching shareToken and add the user's UID to the Trip's collaboratorIds array
2. WHEN the join operation succeeds, THE App SHALL redirect the user to the Trip_Detail_Page for that trip
3. WHEN an unauthenticated user navigates to `/join/:shareToken`, THE App SHALL redirect the user to the login page and return the user to the join link after successful authentication
4. IF the shareToken does not match any Trip, THEN THE Join_Trip_Page SHALL display an error message indicating the link is invalid or expired
5. IF the user is already a Collaborator or the Owner of the Trip, THEN THE Join_Trip_Page SHALL redirect the user directly to the Trip_Detail_Page without modifying collaboratorIds

### Requirement 16: Participant Protection

**User Story:** As a trip owner, I want to be prevented from removing participants who are referenced in expenses, so that expense data integrity is maintained.

#### Acceptance Criteria

1. WHEN the Owner attempts to remove a Participant name from the participants list, THE App SHALL check whether that name appears as paidBy or in sharedBy on any existing Expense in the Trip
2. IF the Participant name is referenced in any Expense, THEN THE App SHALL prevent the removal and display a message explaining the participant cannot be removed while referenced in expenses
3. THE App SHALL visually indicate which participants are removable and which are protected by expense references

### Requirement 17: UI Design and Responsiveness

**User Story:** As a user, I want a clean, modern, and responsive interface, so that I can use the app comfortably on any device.

#### Acceptance Criteria

1. THE App SHALL use a white background with soft gray cards, subtle shadows, and rounded-xl corners
2. THE App SHALL use blue-600 as the primary accent color and emerald-500 as the success color
3. THE App SHALL use shadcn/ui components (Button, Card, Input, Select, Checkbox, Dialog, Avatar) for all interactive elements
4. THE App SHALL be fully responsive with a mobile-first design approach
5. THE App SHALL display loading skeletons during data fetching
6. WHEN an error occurs during data operations, THE App SHALL display an error toast notification using sonner

### Requirement 18: Deployment

**User Story:** As a developer, I want to deploy the app to Firebase Hosting, so that users can access it via a public URL.

#### Acceptance Criteria

1. THE App SHALL be deployable to Firebase Hosting using a single `firebase deploy` command
2. THE App SHALL include Firebase configuration for Authentication (Google provider) and Cloud Firestore
3. THE App SHALL include Firestore security rules as defined in the security rules specification
